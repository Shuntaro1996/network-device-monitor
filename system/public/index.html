📖 Iperf3 コマンド詳細解説
▼ 基本オプション
  • -p [PORT] : ポート番号 (デフォルト: 5201)
  • -t [SEC] : 計測時間 (デフォルト: 10秒)
  • -i [SEC] : 中間結果の表示間隔
  • -u : UDPモードで計測 (デフォルトはTCP)
  • -b [N] : 帯域制限 (UDP時はデフォルト1Mbps)
  • -P [NUM] : 並列ストリーム数（同時セッション）
  • -R : リバースモード（サーバー側から送信）
  • -s : サーバーモードで待機 (ポート 5201)
  • --forceflush : 出力をバッファリングせず即時出力
▼ 応用・詳細オプション
ネットワーク特性の調整
  • --mss [N] : TCP 最大セグメントサイズ (MSS) の指定
  • -w [N] : ウィンドウサイズ / ソケットバッファサイズの指定
  • -M [N] : MTU（最大伝送単位）の最大値を設定
  • -N : TCP 遲延なし (Nagleアルゴリズムの無効化)
実行・出力制御
  • -J : 結果を JSON 形式で出力（解析用）
  • --logfile [F] : 結果を指定したファイルに保存
  • -f [K/M/G] : 表示単位 (Kbits, Mbits, Gbitsなど)
  • --get-server-output : サーバー側の出力も取得する
▼ 📊 TCPモード vs UDPモード 取得情報・使い分け
取得・測定項目 TCP モード (デフォルト) UDP モード (-u 指定)
実効帯域幅 (Mbps) ✅ 最大伝送能力を実測 ✅ 指定レート (-b) に対する実測値
転送データ量 (Bytes) ✅ 送信・受信の総データ量 ✅ 送信・受信の総データ量
パケット再送数 (Retransmits) ✅ 再送回数を検出 (品質指標) — (再送制御なし)
パケットロス率 (%) — (自動再送されるため) ✅ 消失パケット数 & ロス率(%)
ジッター / 揺らぎ (ms) — ✅ パケット到達間隔のブレを測定
主な測定用途 ファイル転送・Web等の最大速度測定 IP電話・Web会議・動画の品質・遅延ブレ評価
💡 TCPモードのポイント:
確実な転送を行うため、パケットロスが起きると再送が発生して速度が低下します。複数並列で限界を測る場合は -P 4 などの指定が効果的です。
💡 UDPモードのポイント:
再送を行わないため、回線の素のパケットロスやジッターを正確に測定できます。計測時は帯域指定（例: -u -b 50M）を付けるのが推奨されます。
※ 計測対象の機器で iperf3 がサーバーモード (`iperf3 -s`) で動作している必要があります。
※ 計測中はネットワーク帯域を消費するため、業務通信への影響にご注意ください。

    操作ガイド & ネットワーク用語集

    🚀 監視の基本的な流れ

    1. 自動監視スタート: サーバー起動と同時に、登録済みの全機器に対してバックグラウンドでPing送信・死活監視が開始されます。
    2. ダッシュボードで状態確認: 画面上で各機器の稼働状態（🟢 正常 / 🔴 障害 / ⏸ 停止）、応答遅延、ジッター、パケット損失率がリアルタイム（1秒間隔）で更新されます。
    3. 機器の追加・管理: 左メニュー「🖥 機器追加 / 管理」からIPアドレスを指定して追加、または「🔍 自動探索スキャン」でネットワーク内の機器を一括発見・登録できます。
    4. 点検報告書の作成: 右上の「📄 点検報告書 (PDF/印刷)」ボタンを押すと、期間内の総Ping数・稼働率(SLA)・応答遅延グラフをまとめたA4印刷向けレポートが自動生成されます。

    🖥️ 画面の見方・機能一覧

    📊 ダッシュボード
    全機器の一覧とリアルタイム遅延グラフ。グループ別のタブ切り替え、機器ダブルクリックでの詳細SNMP情報確認、ホバーでのグラフ強調表示が可能です。
    🌐 システム構成図 (トポロジー)
    機器同士の接続関係（親子関係）をビジュアルなネットワーク図で可視化。ドラッグ配置やポート接続情報の確認が直感的に行えます。
    🚀 Iperf3 帯域計測
    ネットワーク機器間の実効通信速度（送信 Tx / 受信 Rx Mbps）を測定。TCP/UDP両対応でボトルネックを特定します。
    📡 Syslog / Trap 受信
    ルーターやスイッチが送信するシステムログ（LinkDown、認証エラーなど）をリアルタイムに受信・一覧表示します。
    SLA / 到達率 到達率（稼働率 %）
    送信したPing総数に対して、機器から正常に応答が返ってきた回数の割合です。
    💡 目安: 99.9%以上 が一般的な企業ネットワークの可用性基準（年間停止時間8.7時間以内）です。
    Jitter ジッター（通信の揺らぎ / ms）
    連続するPing応答時間の「ブレ・ばらつき」を表す指標です（RFC 3550準拠）。
    応答時間が安定していれば 0 に近く、回線混雑やパケット滞留が起きると跳ね上がります。
    💡 目安: 5ms未満 が理想。Web会議（Teams/Zoom）やVoIP通話で音途切れ・映像乱れを防ぐ重要な品質指標です。
    Outage 瞬断時間 & 瞬断回数（600ms / 5000ms 閾値）
    ネットワークが一時的に切断されてから復帰するまでの「連続オフライン時間（ミリ秒 / ms）」です。
    600ms以上瞬断: Wi-Fiローミングや回線瞬断など、Web会議で一瞬音声が途切れるレベルの障害。
    5000ms (5秒) 以上瞬断: アプリケーションのセッション切断や再接続が発生する重大な通信断。
    ※ 瞬断回数は、通信断から正常復帰したタイミングで確定カウントされます。
    Dual-Rate 超高頻度監視（0.1s デュアルレート方式）
    最大2台までの重要機器（コアルーターや重要サーバー）を 0.1秒（100ms）間隔 で超高精度監視し、その他の機器は 5.0秒間隔 で継続監視するインテリジェント機能です。
    ネットワーク全体の帯域圧迫を防ぎながら、ミリ秒単位の微小なパケットロスや瞬断を見逃さず検出できます。
    Dependency 親機器依存アラート抑制 (Parent Suppression)
    上位の基幹スイッチがダウンした際、その配下に接続されている数十台のPCやAPが一斉に「オフライン」と判定されて大量のアラートメールが届く現象（アラートの嵐）を自動的に防止します。
    親機器が停止中は配下機器の障害通知を自動で保留・静観します。
    Protocols SNMP / LLDP / CDP / MTR / iPerf3
    SNMP (v2c/v3): 機器のCPU・メモリ使用率、LANポートのリンク速度やトラフィック量を内部取得するプロトコル。
    LLDP / CDP: スイッチ同士が「どのポートにどの隣接機器が繋がっているか」を自動交換するプロトコル。
    MTR (Visual Tracert): 目的の機器までの経路途中（ホップ）のどこで遅延やパケットロスが起きているかを連続測定する経路診断ツール。
    iPerf3: 実際に大容量パケットを流して最大通信速度（Mbps）を測定するベンチマークツール。
    ❓ 機器が「🔴 障害（オフライン）」と表示されたらどうすればいいですか？
    1. まず上位のルーターやハブが正常か確認してください（親機器がダウンしている場合は配下全体がオフラインになります）。
    2. 対象機器カードの「🔍 MTR」ボタンを押して、経路上でどのルーターから応答が途絶えているか確認します。
    3. 機器のLANケーブル抜け、電源断、IPアドレス重複がないか現地を確認してください。
    ❓ アラート通知（メール / Webhook）が届きません
    1. 左サイドバーの設定（または管理設定モーダル）で「🔔 Webhook通知」または「📧 メール通知」が「有効」になっているか確認してください。
    2. メール設定の場合、「テスト送信」ボタンを押してSMTPサーバーへの接続が可能かテストしてください。
    3. 「親機器がダウン時は配下アラートを抑制」がONの場合、上位機器がオフラインの間は配下機器の通知は自動的に保留されます。
    ❓ 長期間運用するとハードディスクの容量を圧迫しませんか？
    本システムには 「ログ自動クリーンアップ機能」 が標準搭載されています。
    デフォルトでは30日を超過した古いセッションログ（Reportsフォルダ）が自動で安全削除されるため、ディスク容量がパンクする心配はありません。
    保持日数は「🖥 機器追加/管理」→「システム設定」→「🧹 メンテナンス＆ログ」から7日〜180日へ自由に変更可能です。
    ❓ ブラウザを閉じたら監視は止まりますか？
    ブラウザの閉じるボタンを押すと、ハートビート途絶検知によりサーバーは安全にログを保存して終了します。
    再度監視を開始する場合は、PowerShell または起動バッチからサーバーを起動してください。
