💡 運用上の安心設計ポイント

  • 誤操作の防止: 日常の点検作業では、ルートにある Start-Monitor.bat をダブルクリックするだけで起動できます。system/ フォルダ内のソースコードや設定ファイルを誤って触ったり削除したりする心配がありません。
  • 選択プロンプトの自動進行（デフォルト値「4」の適用）: システムのセットアップや各種確認プロンプトにおいて、都度の数値選択が求められる場面では、運用ルールに基づき原則として 「4」 を選択したものとして自動進行します（※OS設定の変更や重要データ削除など、破壊的変更を伴う操作を除く安全設計です）。

2. システムの起動と終了

起動手順

  1. 本フォルダ内にある Start-Monitor.bat をダブルクリックします。
  2. 高速・前提モジュール自動診断（約0.3秒）:
    • 起動直後に、文字コード整合性（UTF-8 BOM キャッシュ判定）および PowerShell バージョン・SNMP 通信モジュール の導入状態が超高速（約0.3秒）で自動検査されます。
    • 初めての PC や別端末にフォルダごとコピーした場合など、もし SNMP モジュールが未導入であれば 「SNMP モジュールを今すぐ自動インストールしますか？ [Y/N]」 と表示されます。そのまま [Enter] キーを押すだけで自動インストールが完了し、監視サーバーが立ち上がります。
  3. 黒いコマンド画面（PowerShell）が起動します。これは 監視処理を行うバックグラウンドサーバー（Watchdog 自己治癒機能付き） です。監視中は閉じないでください。
  4. サーバー準備完了と連動したブラウザ自動起動:
    • Watchdog が 0.2秒間隔でサーバーの応答開始（/api/health）を確認し、Webサーバーの受け入れ準備が100%整った瞬間に自動でブラウザを立ち上げ、監視ダッシュボード（http://localhost:8081）を表示します（手動リロード不要で最初から確実に表示されます）。

💡 ヒント: 以前に登録した機器情報や設定（表示位置・閾値・通知設定など）はすべて自動的に読み込まれます。

終了手順

  1. 画面から終了する場合（推奨）:
    • ダッシュボード上部の 「🛑 監視終了＆報告書」 ボタンをクリックします。
    • 確認ダイアログで「終了して報告書を開く」を押すと、最新の点検報告書（HTML/PDF）が別タブで自動的に開き、バックグラウンドサーバーが安全に停止 します。
  2. コマンド画面から終了する場合:
    • バックグラウンドの黒いPowerShell画面で [Enter] キーを押すか、ウィンドウを閉じます（または Ctrl+C を入力すると安全に終了処理が実行されます）。
  3. 終了時に直近の監視セッションサマリー（稼働率・パケットロス率・ジッター・最大瞬断時間など）がCSVファイルに自動保存されます。

⏱️ 24時間365日の連続常時監視（無人運用モード）の設定手順

本システムには、パソコンの省電力と安全のため「画面（ブラウザ）を閉じたらサーバーも自動的に終了する親切設計（連動停止機能）」が標準で備わっています。 これは、家電で例えると「テレビの電源を切ったら、連動してDVDレコーダーの電源も切れる仕組み」と同じです。

しかし、「サーバールームの管理PCで、ブラウザ画面を閉じた状態でも24時間休まずネットワーク監視を続けさせたい」という無人連続運用の場合は、この連動機能をOFF（無効）に設定できます。

設定方法（2通りの方法）

  1. 設定ファイル（config.json）を編集する方法:
    • system/config.json をメモ帳などで開き、以下の行を変更します：
      "autoShutdownOnDisconnect": false
      （※標準値は true です。これを false に変更して上書き保存します）
  2. 環境変数で指定する方法:
    • サーバー起動前に環境変数 NETWORK_MONITOR_AUTOSHUTDOWN=false または AUTOSHUTDOWN_ON_DISCONNECT=false を設定することで、設定ファイル書き換えなしで無人モード起動が可能です。
  3. Web画面から変更する場合:
    • 画面右上の 「⚙️ 設定」 モーダルを開き、連続稼働設定を変更（/api/config 経由で即座に反映）することも可能です。

⚠️ 無人運用時の注意点: 無人運用モード（false）にすると、ブラウザを閉じても監視プログラムはバックグラウンドで動き続けます。監視を完全に終了させたい場合は、黒いPowerShell画面で [Enter] キーを押すか、または画面上部の「🛑 監視終了＆報告書」ボタンから終了してください。

3. ダッシュボードの見方とリアルタイム監視（切断検知バナー・自動復旧含む）

ダッシュボードでは、登録された全機器の通信健全性をリアルタイムに一目で監視できます。

画面上部のユーティリティボタン

画面最上部には、日常の運用をスムーズにする便利なクイックボタンが配置されています。

  • 🛑 監視終了＆報告書: 本日の監視をワンクリックで終了し、点検報告書（HTML）を保存・自動オープンします。
  • 🔇 消音 (10分): 障害発生時の警告音をワンクリックで 10分間一時消音（カウントダウン表示） します。障害調査中のストレスを軽減し、再クリックでいつでも即時解除できます。
  • 📌 障害優先表示 (ON/OFF): 障害（赤）や警告（黄）が発生している機器を 自動的にリストの最上部にピン留め します。スクロールせずに異常機器を瞬時に発見できます。
  • 📄 点検報告書 (PDF/印刷): 監視を継続したまま、現時点でのグラフ付き点検報告書を別タブでプレビュー確認・印刷できます。

📡 サーバー切断検知バナー＆自動再接続トースト（高信頼性UI表示）

本システムでは、ネットワークの一時的な瞬断やPC高負荷によってバックグラウンドサーバーとの通信が途切れた場合でも、画面がフリーズしたり真っ白になったりしない堅牢な保護機能（UIレジリエンス）を備えています。

  1. 🚨 切断検知バナー (#network-offline-banner):
    • サーバーへのステータス取得が3回連続で失敗した場合、画面最上部に赤色固定の 「⚠️ サーバーとの接続が途切れています（自動再試行中...）」 警告バナーが即座に表示されます。
    • バナー右側には 「⚡ 今すぐ再接続」 ボタンが配置されており、自動再試行を待たずに手動で即座に再接続を促すことができます。
    • 切断中も直前の機器カードやトポロジー図の状態が保持され、画面の操作不能やレイアウト崩れを防ぎます。
  2. ✅ 自動再接続トースト (showToast):
    • ネットワークやサーバーが復旧し通信が再開すると、切断バナーは自動的に消去されます。
    • 同時に画面右上に 「✅ サーバーとの再接続が完了しました」 という緑色のトースト通知が表示され、通常のリアルタイム監視へシームレスに自動復帰します。
  3. ⚡ 描画パフォーマンスの最適化（30 FPS制限 & Chart.js即時描画）:
    • トポロジー図の粒子・波紋アニメーションは 30 FPS（毎秒30コマ）に自動調整 され、CPUやGPUの負荷を大幅に削減しています。
    • また、毎秒更新される折れ線グラフはアニメーション補間をバイパス（.update('none')）して高速更新されるため、長時間の常時監視でもブラウザが重くならず快適に動作します。

画面上部・サイドバーのサマリーバッジ

サイドバー上部には、システム全体の稼働ステータスがリアルタイム集計されます。

  • 🟢 正常 ○台: 正常に応答（Ping成功）している機器数
  • 🟡 警告 ○台: 遅延超過または単発パケロスを検知した機器数

📈 折れ線グラフの連携機能（ホバーフォーカスハイライト）

  • 表示期間は約30秒分: 更新間隔（1秒・0.1秒など）にかかわらず、直近およそ30秒間の遅延の推移を表示します。
  • 縦軸は自動調整: 実際の遅延の大きさに合わせて縦軸の目盛りが自動で伸び縮みします（例: 遅延が1〜3msなら0〜3ms程度の目盛り）。小さな遅延の変化も見やすくなります。
  • 警告中も線を表示: 遅延や揺らぎで「警告（黄色）」になっている間も、応答が返ってきていれば値を描画します。線が途切れるのは「応答なし（タイムアウト）」のときだけです。
  • 機器カードの上にマウスカーソルを乗せると、右側の統合グラフで該当機器の折れ線以外がフェードアウト（半透明化）し、注目している機器の波形が一目で際立ちます。
  • グラフ下部の凡例（レジェンド）をクリックすることで、特定の機器のみを表示/非表示に切り替えることも可能です。

4. ⏱ 到達性ヒートマップ（タイムライン）の活用

ダッシュボード上部に配置された 「⏱ 稼働タイムライン (ヒートマップ)」 では、各機器の直近の通信品質がカラーブロックで時系列表示されます。

  • 🟢 緑色ブロック: 正常通信（低遅延）
  • 🟡 黄色ブロック: 高遅延検知（閾値超過）
  • 🔴 赤色ブロック: パケット不達・障害発生（オフライン）
  • ⚪ 灰色ブロック: 監視一時停止中 / データなし

過去にどのような周期で遅延や瞬断が発生していたかをスクロールなしで直感的に俯瞰できます。

5. 機器の登録・編集・グループ管理（デバイス管理 & リモート操作設定）

左サイドバーの 「デバイス管理」 タブから新しい機器の追加や設定変更を行います。

機器の追加手順

  1. IP アドレス: 監視対象のIP（例: 192.168.10.1）を入力（必須）
  2. デバイス名: 表示名（例: フロアスイッチ-2F）を入力（必須）
  3. 監視方式 (Ping / TCPポート):
    • Ping (ICMP): 通常の死活監視（相手が通信に応答するか）を行います。
    • TCPポート監視: Webサーバー（ポート80 / 443）やメールサーバー（ポート25）など、特定のサービスポートが開いているかを直接監視したい場合に指定します。
  4. グループ: 所属するグループを選択、または新規作成（例: 2Fオフィス, サーバー室）
  5. アイコン: 機器種別に応じたアイコン（Switch, Router, AP, Camera, PC 等）を選択
  6. SNMP設定 (任意):
    • v2c: コミュニティ名（通常 public）を入力
    • v3: ユーザー名、認証プロトコル/パスワード、暗号化プロトコル/パスワードを入力
  7. リモート操作設定 (任意):
    • 対象機器に対して遠隔からの再起動やコマンド実行を行いたい場合は、フォーム内の「🔧 リモート管理を有効にする」を設定します（詳細は後述）。
  8. 「機器を追加」（または編集時は「更新」）ボタンをクリックすると即座に監視および設定が反映されます。

🔧 機器登録・編集画面でのリモート操作設定（SSH・WinRM・カスタム・DPAPI暗号化）

本システムでは、監視しているネットワーク機器やPCに対して、異常検知時の再起動や状態確認コマンドをブラウザから遠隔実行できる「リモート管理機能」を備えています。 機器の新規登録時、または機器一覧の「編集」ボタン（鉛筆アイコン）を押して開く編集モーダルから設定できます。

1. リモート管理の有効化（チェックボックス）

  • 「🔧 リモート管理（再起動・コマンド実行）を有効にする」 にチェックを入れます。
  • チェックを入れると、プロトコル選択や認証情報の入力欄が自動展開されます。
  • ※不要な機器や遠隔操作を許可したくない機器では、このチェックを外したままにしておくことで、不用意なコマンド実行を元から防止できます。

2. 接続プロトコル方式の選択と特徴

対象機器のOSやメーカー仕様に合わせて、最適な接続プロトコルをドロップダウンから選択します：

接続プロトコル方式 主な対象機器 仕組みと選び方（噛み砕いた解説）
SSH (Linux / ルーター / スイッチ) Linuxサーバー、ルーター（Cisco, Yamaha等）、L2/L3スイッチ 安全な鍵付きトンネル: 通信内容やパスワードがすべて暗号化される世界標準の遠隔操作プロトコルです。Windows標準のOpenSSHクライアント（ssh.exe）を使用して安全に接続します。
WinRM (Windows リモート / PowerShell) 社内Windows PC、Windows Server Windows公式の遠隔管理機能: PowerShellの遠隔実行（Invoke-Command）やWindows標準の再起動命令（shutdown.exe）を利用し、相手画面を占有することなく裏側から安全に制御します。
カスタムコマンド (ローカルスクリプト・外部CLI) 独自管理スクリプト、専用CLI、外部ツール 自由な外部ツール連携: 自社開発のバッチファイルや独自のコマンドラインツールを本システムから直接呼び出して実行します。コマンド文字列内で {ip}, {name}, {user}, {port} などの変数が自動置換されます。

3. 接続先情報とポート番号

  • ホスト名 / 接続IP: 接続先のアドレス（空欄の場合は、機器本体の登録IPアドレスが自動適用されます）。
  • ポート番号: 接続先サービスの通信ポート番号を指定します：
    • SSH の標準ポート: 22
    • WinRM (HTTP) の標準ポート: 5985 / WinRM (HTTPS) は 5986
    • 独自ポートに変更している場合は、該当のポート番号を入力します。

4. 認証方式と Windows DPAPI による安全なパスワード暗号化

接続時に必要な認証方式を選択します：

  • パスワード認証:
    • ログインユーザー名とパスワードを入力します。
    • SSH のパスワードに日本語などの全角文字が含まれていても、文字化けせずにそのまま送られます。
  • 秘密鍵認証 (SSH Key):
    • パスワードを使わず、秘密鍵ファイルを使って接続する高度な認証方式です。
    • 「SSH 秘密鍵ファイルパス」に鍵ファイルのフルパス（例: C:\Users\username\.ssh\id_rsa）を入力し、パスフレーズがある場合はパスワード欄に入力します。
  • 現在のWindows資格情報:
    • ドメイン参加環境（Active Directory等）において、現在Windowsにログインしているユーザー権限（Kerberos / Negotiate）をそのまま流用して接続します。パスワードの保存が不要なため安全です。
  • 認証なし:
    • 認証が不要な機器や、カスタムスクリプト側で独自に認証を行う場合に選択します。

🔒 安心のセキュリティ機能（Windows DPAPI 暗号化保管）: 入力されたパスワードは、設定ファイル（devices.json）内に平文のまま保存されることは絶対にありません。 Windows OSが標準提供する強固な暗号化機構「DPAPI（Data Protection API）」によって自動的に暗号化（enc:... という暗号文字列）され、そのPCのログインユーザーしか復号できない金庫状態で安全に保管されます。 万が一設定ファイルが第三者にコピーされたり流出したりした場合でも、パスワードが平文で漏洩するリスクはありません。

🚧 他のパソコンからの接続の遮断: 監視画面と操作の窓口は、監視ツールを動かしているこのパソコンからしか使えません。他のパソコンから接続してきた場合は、相手のアドレスを確認して門前払い（エラー 403）します。他のパソコンから監視画面を見ることはできないので、このパソコンで操作してください。 ただし、このパソコンを一緒に使っている他のユーザーや、このパソコンで動いている他のプログラムからの接続は区別できません。信頼できる人だけが使うパソコンで動かしてください。

🛡️ 外部サイトからの「なりすまし操作」の遮断: 監視画面と同じブラウザで別のWebサイトを開いていても、そのサイトが裏でこっそり再起動やコマンド実行を指示することはできません。 ブラウザは「どのサイトからの依頼か」を自動で書き添えて送ってくるため、監視画面（http://localhost:8081）以外からの依頼はサーバーが門前払い（エラー 403）します。 また、入力したコマンドに " や } などの記号が含まれていても、それが「監視しているこのPC上での命令」として誤って実行されることはなく、必ず相手の機器へコマンドとしてそのまま届けられます。 ※ プロトコル「カスタム」は、仕様上このPC上でコマンドを実行する方式です。信頼できるコマンドだけを登録してください。

5. 再起動コマンドの指定 (Reboot Command)

  • ワンクリック再起動ボタンを押した際に発行される再起動コマンドを指定します。
  • 空欄のままでも安心: 空欄の場合は、選択したプロトコルの標準コマンドが自動的に使用されます：
    • SSH: sudo reboot
    • WinRM: パスワード認証を設定していれば、そのユーザー名・パスワードで Restart-Computer -Force を実行します。認証を設定していない場合は、このPCにログインしている人の権限で shutdown.exe /m \\<IP> /r /t 0 /f を実行します。
    • カスタム: 機器固有の再起動コマンドを入力（例: restart-device.bat {ip}）
  • WinRM で再起動コマンドを入力した場合は、そのコマンドが（設定したユーザー名・パスワードで）相手のPC上で実行されます。
  • カスタムで使える置き換え文字は {ip}, {name}, {user}, {port} の4つです。
  • コマンドの実行やログ取得に時間がかかっても、監視画面の更新は止まりません（裏側の別の作業場所で実行されます）。

6. 登録カスタムコマンド一覧（プリセットコマンドの管理）

日々の点検やトラブルシューティングで頻繁に使用するコマンドを「プリセット（お気に入り）」として登録しておけます：

  • 表示名: 一覧に表示される分かりやすい名称（例: 稼働時間確認, ルーティングテーブル表示, Webサービス再起動）
  • 説明: コマンドの用途や注意書き（例: uptimeを表示します）
  • 実行コマンド: 実際に送信するコマンド文字列（例: uptime, show ip route, systemctl restart nginx）
  • 「追加」ボタン: クリックするとリストに即時追加されます。不要になったコマンドは右端の赤い「🗑 削除」ボタンでいつでも削除できます。
  • ここで登録したコマンドは、後述の「詳細診断画面（🔧 リモート操作タブ）」のドロップダウンからワンクリックで選択して実行できます。

6. ⚙️ 設定（監視・通知・バックアップ・保守）

設定画面では、監視パラメータ・通知・バックアップ・保守の管理を行えます。

① 監視・閾値タブ

  • 基本ポーリング間隔 (ms): 通常監視の実行間隔（デフォルト: 1000ms）。
  • 0.1s 超高頻度デュアルレート監視:
    • 100ms を選択すると、最重要ターゲット最大2台を0.1秒間隔、その他の機器を5.0秒間隔 で並行監視するデュアルレートモードが発動します。
    • 対象機器①・②をドロップダウンから選択します。
    • ※ Ping自体は0.1秒ごとに行われ、ロス率・瞬断の判定も0.1秒単位ですが、画面の表示更新は0.2秒ごと に抑えています（サーバーへの問い合わせが混み合って画面が止まるのを防ぐため）。
    • ※ 対象外の機器（5秒間隔）の応答待ちで0.1秒監視が止まらないよう、対象外機器の結果は届いたものから順に反映されます。
    • ※ ダッシュボードの「遅延推移」グラフには、対象外の機器（5秒間隔）も 点線 で表示されます。凡例の名前の後ろに (5.0s) と付きます。値は5秒ごとに更新されるため、線は階段状になります。（ダッシュボードの機器カードには、対象機器だけが表示されます）
  • Ping 送信データサイズ (bytes): ICMP Echo ペイロードサイズ（デフォルト: 1 byte、最大: 65,500 bytes）。
  • 遅延アラート閾値 (ms): 警告を発するPing遅延時間（デフォルト: 100ms）。
  • 瞬断判定閾値① / ② (ms): 瞬断回数をカウントする判定閾値（デフォルト: 600ms / 5000ms）。

② 通知・音声タブ

  • 🔊 Web Audio 音声アラート:
    • 障害検知時（オフライン化・高遅延時）にブラウザ上で警告音（ビープ音/チャイム）を自動生成して鳴らします。
    • 音量スライダーで音量を調節し、「🔊 テスト再生」で事前に確認できます。
  • 🔔 Webhook 外部通知:
    • Slack, Microsoft Teams, Discord 等の Incoming Webhook URL を登録することで、障害発生・復旧時に自動で通知メッセージを送信します。
    • 「🔔 テスト送信」ボタンで、URLの疎通確認が可能です。

③ バックアップ・復元タブ

  • 📥 設定バックアップのダウンロード:
    • 登録されたすべての機器情報（IP、名前、グループ、SNMP設定、トポロジー座標）とシステムパラメータを1つの .json ファイルとしてダウンロードします。
  • 📤 バックアップから復元:
    • バックアップ .json ファイルを選択して「適用・復元」を押すだけで、別PCへの移行や過去の構成への復元が1クリックで完了します。

④ ログ保守タブ

  • ログ自動クリーンアップ保持日数:
    • 指定した日数（例: 30日）を超過した古いセッションログフォルダーを自動的に安全削除し、ストレージ容量の逼迫を防ぎます。
    • 削除は起動時・終了時に加えて、動作中も6時間ごとに行います（無人運用で長期間動かし続けても溜まり続けません）。同じタイミングで、system\debug.log が 5MB を超えていれば debug_1.log に切り替えます。

🌟 描画強化機能（ビジュアル監視）

ネットワークの健全性やデータの流れが一目でわかる5つのビジュアル機能が備わっています。

  1. 🌊 リアルタイム通信量・彗星パケット粒子アニメーション:

    • 機器間の接続線上を、実際の通信速度（Mbps：メガビット毎秒＝1秒間に送受信されたデータ量）に合わせて、尾を引く光の粒（パケット彗星）が滑らかに流れます。
    • 双方向の流れ: 端末から親機器への「上り送信（↑TX）」と、親機器からの「下り受信（↓RX）」のデータがそれぞれの方向に流れるため、どちら向きに通信が発生しているかが直感的に把握できます。
    • 通信量が多い回線ほど粒子の移動速度が速く、数も多くなり、回線が切断（オフライン）した場合は自動でパケットが止まります。

  2. 🫀 障害・警告ノードの脈動レーダー波紋（Radar Ripple Rings）:

    • 応答が途絶えた 「障害（赤色）」 や、遅延・パケットロスが増加した 「警告（黄色）」 の機器の周囲に、ソナー・レーダーのような光の波紋リングが外側へ脈動して広がり続けます。
    • 多数の機器が並ぶ大規模なネットワーク図でも、どの機器でトラブルが起きているかが遠目からでも一瞬で判別できます。

  3. 🎨 動的トラフィックヒートマップ＆中央スループットバッジ:

    • 接続線の色が、流れているデータの通信量（負荷）に応じてリアルタイムに変化します：
      • 青 / シアン（水色）: 低負荷・アイドル通信（5 Mbps未満）
      • 緑色: 通常通信（5 ～ 25 Mbps）
      • オレンジ色: 中〜高負荷通信（25 ～ 75 Mbps）
      • ネオン赤紫（マゼンタ発光）: 帯域逼迫・大容量通信（75 Mbps以上）
      • 赤色破線: 障害・回線断線
    • 接続線の中央には 「↑12.4M / ↓45.8M」 のように、現在の送信・受信速度をコンパクトに表示するピルバッジ（数値タグ）が常時表示されます。

  4. 📐 ワンクリック「階層ツリー自動整列」:

    • 操作バーの 「📐 階層ツリー整列」 ボタンをクリックすると、機器の役割や親子接続関係を自動解析し、以下の綺麗な階層（ツリー型）へ自動的に再配置します：
      • 最上段（Tier 0）: インターネット / ゲートウェイルーター
      • 第2段（Tier 1）: コアスイッチ / ブリッジ装置
      • 第3段（Tier 2）: エッジスイッチ / Wi-Fiアクセスポイント
      • 第4段（Tier 3）: 各種端末・カメラ・サーバー・デコーダー・PC
    • 整列後の座標は自動保存されるため、次回起動時も美しいレイアウトがそのまま維持されます。

  5. 🌐 CADテック背景グリッド ＆ 🖥️ シアターモード ＆ ⚡ アニメーションFX切替:

    • サイバーパンク/CADテック背景グリッド: ネットワーク運用センター（NOC）のモニターを模した精密な方眼グリッドと照準十字が背景に描画され、マウスによる拡大・縮小（ズーム）や画面移動（パン）にリアルタイムで追従します。
    • 🖥️ シアターモード: 構成図を画面いっぱいに最大化表示します。大型ディスプレイや監視モニターに常時映し出す際に最適です。[Esc] キーまたは「🖥️ 通常表示」ボタンでいつでも元の画面に戻せます。
    • ⚡ アニメーションFX切替: 光の粒子や波紋アニメーションの ON / OFF をワンクリックで切り替えます。PCへの負荷を最小限に抑えたい環境や、静止した図面として確認したい場合に活用できます（設定は自動保存されます）。

8. 詳細診断モーダル（ダブルクリックで起動 ＆ 🔧 リモート操作）

ダッシュボード上の機器カードを ダブルクリック（または機器カード右端の「🔍 詳細」ボタンをクリック）すると、エンジニア向けの詳細診断画面が開きます。

  1. 📊 ポート・トラフィック詳細:
    • 各ネットワークポートの通信速度（Mbps）、エラーパケット数、破棄パケット数をリアルタイム監視。
  2. 📍 経路診断（MTR）:
    • 対象機器までのルーティングホップを自動追跡し、各ルーターでの遅延とパケットロス率を診断。
  3. 📈 24時間 履歴トレンド:
    • 過去24時間の遅延・通信量の推移をグラフで遡って確認（日本語・英語ヘッダーのログを自動認識して綺麗に描画されます）。
  4. 🔧 リモート操作タブ（ワンクリック再起動・コマンド実行・安全二重確認）:
    • 対象機器に対する遠隔再起動や任意のコマンド実行を、安全な二重確認ダイアログとリアルタイム出力コンソール付きで行える強力なメンテナンス機能です（詳細は以下で詳しく解説します）。
  5. 📋 機器ログタブ（機器のカルテ取得・リアルタイム検索・ダウンロード・過去ログ履歴）:
    • ルーターやサーバーなどの機器から内部システムログ（健康状態を記録した「カルテ・健康日記」）をワンクリックで遠隔取得し、検索ハイライトやローカル保存、過去ログの再ダウンロードを行えるトラブルシューティング機能です（詳細は後述）。

  • 入力後、右側の 「⚡ 任意実行」 ボタンをクリックします。

🛡️ 安全機能：二重確認ダイアログ（誤操作・通信断の防止）

ネットワーク機器の再起動や設定変更コマンドは、対象機器を間違えると社内業務や現場カメラの録画が止まるなど重大な通信事故につながるリスクがあります。 本システムでは、人的ミスによる誤操作を徹底的に防止するため、「車のサイドブレーキ＋確認指差し喚呼」 のような二重確認機構を義務付けています：

  1. 二重確認モーダルの強制ポップアップ:
    • 「再起動」または「コマンド実行」ボタンをクリックすると、画面全体が暗転し、赤枠で警告された 「⚠️ リモート操作の実行確認」 ダイアログが最前面に表示されます。
  2. 対象機器名・IPアドレスの巨大明示:
    • ダイアログ内に、対象となる 「機器名（例: コアルーター）」 と 「IPアドレス（例: 192.168.1.1）」、および 「実行動作（例: 再起動 (Reboot) または 実行コマンド名）」 が大きく強調表示されます。
    • 「本当にこの機器に対して実行してよいか」を落ち着いて最終確認できます。
  3. 通信影響への注意喚起とチェックボックス:
    • 「再起動中は対象機器およびその配下の通信が一時的に切断され、業務に影響を与える可能性があります」という警告文が表示されます。
    • 「上記の対象機器および通信影響を確認しました」チェックボックスの確認を促します。
    • このチェックは確認画面を開くたびに外れた状態から始まります。自分でチェックを入れるまで「⚡ 実行する」ボタンは押せません（うっかりクリックによる誤操作防止）。
  4. キャンセルによる安全中断:
    • 対象機器を間違えた場合や、実行を取りやめたい場合は、左下の 「キャンセル」 ボタン、右上の 「×」 ボタン、またはキーボードの [Esc] キーを押すことで、一切の通信を行わずに即座に安全中断 されます。

🖥️ 実行結果・標準出力コンソールの見方

確認ダイアログで「⚡ 実行する」をクリックすると、バックエンドサーバー経由で安全にコマンドが送出され、診断画面下部の 「実行結果・標準出力コンソール（黒いターミナル画面）」 にリアルタイムで結果が出力されます：

  • ステータス表示点 (remote-exec-status-dot):
    • 🟢 緑色点: コマンドが正常に完了しました（Status: COMPLETED）
    • 🔴 赤色点: コマンド実行が失敗、またはタイムアウトしました（Status: FAILED, TIMEOUT, ERROR）
  • 終了コード (Exit Code):
    • 相手OSから返された終了ステータス番号です。一般的に 0 であれば正常終了、それ以外の数値は異常終了を表します。
  • 処理時間 (Duration):
    • コマンド送信から応答完了までにかかった時間（例: 240ms）。
  • 標準出力 (stdout) / 標準エラー出力 (stderr):
    • コマンドが画面に出力したテキスト内容がそのまま表示されます。設定内容の確認結果や、エラー発生時の詳細メッセージを正確に読み取ることができます。
  • コンソール操作ボタン:
    • 📋 コピー: コンソール内のログ全文をクリップボードにコピーします。作業日報や障害報告メールへの転記がスムーズに行えます。
    • 🗑 ログ消去: 画面のコンソール表示をクリアし、待機中状態に戻します。

📋 「機器ログ」タブの使い方とカルテ閲覧機能

詳細診断画面の上部タブバーにある 「📋 機器ログ」 をクリックすると、対象機器のシステムログ取得・閲覧パネルが開きます。 （※対象機器のリモート管理設定が無効になっている場合は、「現在、この機器のリモート管理機能は無効です」と注意文が表示され、誤操作を防ぎます）

💡 なぜ「機器ログ」が必要なのか？（日常生活の例え）

ネットワーク機器（ルーターやスイッチ、サーバー等）は、人間で言えば病院の患者さんのようなものです。 外からPingを送って応答があるかどうかを確かめるのは 「脈拍を測る（生きているかの確認）」 にすぎません。 「なぜか時々ネットが遅くなる」「特定の時間だけ接続が切れる」といった原因を探るには、機器の体の中で何が起きていたのかを記録した 「電子カルテ・健康日記（システムログ）」 を直接めくって調べる必要があります。 本機能は、わざわざ専用の黒い画面（SSHクライアントやTeraterm等）を立ち上げることなく、ブラウザ上から安全なホットライン（暗号化通信）を通じてワンクリックで最新のカルテを取得・診断できる ように設計されています。

② 「📄 今すぐログを取得」ボタンと取得待機アニメーション

  • コマンドを選択（またはカスタム入力）したら、右側の 「📄 今すぐログを取得」 ボタンをクリックします。
  • 取得処理が始まると、ボタン内に 青いローディングスピナー（くるくる回る歯車アニメーション） が表示され、ボタンが自動的に無効化（二重連打防止）されます。
  • バックグラウンドのサーバーが安全な暗号化ホットライン（SSH / WinRM）で機器に接続し、ログを回収します。
  • 取得が完了すると、最新ログが画面のコンソールに即座に展開されます。

③ 黒いコンソール画面（ダークテーマ・等幅ログビューアー）

  • 画面中央の大きな黒いコンソールエリア（device-log-viewer）に、取得したログが綺麗に表示されます。
  • 等幅フォント（Monospace） を採用しているため、ルーターのテーブル表示や日時の桁数が綺麗に揃い、視認性が抜群です。
  • 上部には 「機器名 (IPアドレス)」「取得日時」「行数」「データサイズ（バイト数）」「所要時間（ミリ秒）」 をまとめたヘッダーが自動付与されます。

④ リアルタイムキーワード検索と「一致行のみ絞り込み」機能

何百行・何千行にも及ぶログから、トラブルの手がかりを見つけ出すための強力な2重検索ツールが備わっています：

  1. 🔍 リアルタイム・ハイライト検索:
    • 検索ボックスに error, down, fail, warn などのキーワードを入力すると、ログ内の該当単語が 黄色い蛍光ペン（<mark> タグ） でリアルタイムに光ってハイライト表示されます。
  2. 🔘 一致行のみ絞り込みスイッチ:
    • 検索ボックス右側の 「一致行のみ絞り込み表示」 スイッチ（トグルボタン）を ON にすると、正常なログ行を一時的に隠し、キーワードを含む問題の行だけを抜き出してリストアップ します。
    • 大量の正常ログに埋もれた「回線切断」や「認証失敗」の兆候を一瞬で浮き彫りにできます。

⑤ ログの転記・ローカル保存（クリップボード ＆ ダウンロード）

取得したログは、現場での報告やメーカーへの問い合わせ用に簡単に持ち出せます：

  • 📋 クリップボードにコピー:
    • ボタンをクリックすると、現在画面に表示されているログ全文が一瞬でPCのクリップボードにコピーされます。Slack、Teams、メールへの貼り付けがスムーズです。
  • 💾 ログ保存 (.log):
    • ボタンをクリックすると、{IPアドレス}_{取得日時}.log という分かりやすい名前のテキストファイルとして、お使いのパソコンの「ダウンロード」フォルダに直接保存されます。

⑥ 過去ログ履歴一覧カード（いつでも再ダウンロード可能）

  • 画面下部の 「📁 過去の取得ログ一覧」 エリアには、過去に対象機器から取得されたログファイルが時系列で一覧表示されます。
  • 表示項目: 「取得日時」「実行コマンド」「ログ行数」「ファイルサイズ（KB）」
  • 各行の右端にある 「📥 再ダウンロード」 ボタンをクリックすれば、過去のトラブル発生時のログファイルをいつでも即座に手元のPCへ再ダウンロードできます。

🛡️ 堅牢な安全ガード機構（1MB / 5MB バッファ＆ディスク保護）

機器ログの取得では、時に数十メガバイトに及ぶ巨大なログが吐き出され、ブラウザが固まったりPCのハードディスクが一杯になってしまうリスクがあります。本システムでは2重の防護壁を設けています：

  1. 1MB stdout レスポンス保護（画面フリーズ防止）:
    • 画面へ返却するログテキストが 1,000,000 文字（約1MB）を超えた場合、ブラウザ画面のクラッシュを防ぐため、画面表示を1MBで安全に切り詰めます（末尾に [TRUNCATED: 出力サイズが1MBを超過したため画面表示を切り詰めました...] という親切な案内が表示されます）。
    • サーバー側には全量保存: 画面表示が切り詰められた場合でも、サーバーのディスク（Reports/device_logs/）には省略なしの完全なログファイルが丸ごと保存されているため、後から全量を安全に確認・ダウンロードできます。
  2. 5MB ディスク保存上限ガード（ストレージ溢れ防止）:
    • 万が一、機器から際限なくログが出力され続けた場合でも、サーバー側ファイル保存時に 5MB（約524万文字）で強制的に書き込みを制限し、ディスク容量の圧迫事故を未然に防止します。
  3. プロセス強制終了（Timeout Kill）:
    • 相手先機器のフリーズやネットワーク遅延により応答が返ってこない場合、設定秒数（標準20秒）が経過すると内部プロセス（proc.Kill()）が即座に起動し、処理を安全に自動中断します。

9. 帯域計測（Iperf3 計測）

回線の実効通信速度（スループット）を測定するツールです。

  1. サイドバーの 「Iperf3 計測」 タブを開きます。
  2. 対象PCを選択するか、「カスタム入力」でIPアドレスを指定します。
  3. 計測秒数（例: 10秒）を指定して 「計測開始」 をクリックします。
  4. 1秒ごとのスループットグラフとコンソール出力がリアルタイムに表示され、完了時に Reports/ フォルダへログが自動保存されます。

【UDP の計測では、相手側のログも自動で取得します】

  • カスタムオプションに -u（UDP）を指定すると、相手側（サーバー側）のログも計測の終わりにこのパソコンへ届くので、相手の機器まで取りに行く必要がありません。TCP の計測では取得しません。
  • 相手側のログは画面には表示しません。「💾 サーバー側ログ」 ボタンでダウンロードできます。ファイルは Reports/<起動日時>/remote_iperf_<IPアドレス>.log にも保存されます。ボタンで取得できるのは今回の起動分だけで、再起動の前の分はこのファイルを開いてください。
  • 計測中にブラウザを閉じても、計測とログの取得が終わるまでツールは動き続け、そのあとで終了します。
  • UDP の計測中に「監視終了＆報告書」ボタンを押すと、計測の完了を待ち、相手側のログを自動でダウンロードしてから終了します（ファイルにも保存されます）。
  • UDP の計測中に Enter キーを押したときも、完了を待ってログをファイルに保存してから終了します。急いで止めるときは、もう一度 Enter キーを押してください（相手側のログは保存されません）。
  • 回線が切れるなどで計測が正常に終わらなかったときは、相手側のログを受け取れないことがあります。

【安全設計（帯域負荷防止）】

  • Iperf3 による実パケット送受信は、画面上の 「計測開始」ボタンを押したときのみ 実行されます。
  • 通常の常時バックグラウンド監視で iperf が勝手に実行されることはありません。ダッシュボードと構成図の通信量（Mbps）は、SNMP（機器から通信量を読み取る仕組み）で取得できる機器だけに表示され、取得できない機器は「-」になります。
  • 以前の版では Ping の応答時間から計算した値を「BW: ○○ Mbps」と表示していましたが、実際の通信量とは関係がないため廃止しました。OBR のように SNMP がない機器は、電波の強さと通信速度で「つながり方の品質」を確認してください（通信速度は接続の上限の速さで、実際に流れている量ではありません）。

10. ログ・CSVサマリーレポート・操作履歴（Audit Log）の確認

監視中のデータおよび操作記録はすべて Reports/ フォルダ内に自動整理されて保存されます。

自動出力されるファイル

  1. <IPアドレス>.csv (Reports/sessions/<起動日時>/ 配下):

      • 60秒ごとの軽量チェックポイント保存（_checkpoint.json）: 1分ごとにメモリ上の最新統計カウンタのみを瞬時（1ミリ秒未満）に保存するため、万が一のPC強制終了時も集計値が保護され、何時間・何日計測してもPing間隔が遅延しません。

      • 相手先サーバーの停止や通信不通（Connection refused, Timed out, unable to connect 等）により計測に失敗した試行のログは、ログファイル（iperf_<IP>.log）および点検報告書から自動的に除外・削除（ロールバック） され、正常に測定できたログのみが綺麗に保存されます。

  3. {IPアドレス}_{タイムスタンプ}.log (Reports/device_logs/ 配下):

    • 詳細診断画面の「📋 機器ログ」タブから取得されたシステムログファイル。
    • 自己記述型ヘッダー付き保存: ファイル先頭に、後からログ単体を開いても「いつ・誰が・どの機器から・どんなコマンドで取得したか」が完全にわかるように、以下のメタ情報ヘッダーが自動記録されます：
      ================================================================================
 Network Device Monitor - Remote Device Log
 Device: コアルーター (192.168.1.1)
 Protocol: ssh
 Command: show logging
 Timestamp: 2026-10-24 14:00:00
 Status: COMPLETED | ExitCode: 0 | Duration: 240ms
 Lines: 150 | Size: 12450 bytes
================================================================================
[OUTPUT]
(ここに実際の機器ログ本文が記録されます)
    • 🛡️ 過去レポート自動パージに対する非破壊保護:
      • 定期保守機能（Invoke-PurgeOldReports）で古い監視セッションやCSVが整理・削除される場合でも、Reports/device_logs/ フォルダおよび機器ログファイルは「重要な証跡・カルテ」として保護され、絶対に削除されません。

  4. audit.log（操作履歴・監査ログ - Reports/audit.log）:

    • 本システム上で行われたすべての「設定変更」「機器削除」、および「リモート再起動」「コマンド実行」「機器ログ取得」が、改ざん防止の監査証跡として Reports/audit.log に自動記録されます。
    • Windows OS の名前付きミューテックス（Local\NDM_AuditLog_Mutex）による排他制御を備えており、複数人が同時に操作したり高負荷がかかったりしてもログの書き込み競合（文字化けやファイル破損）が絶対に起きないスレッドセーフ設計です。
    • 日常生活で例えると 「入退室管理記録簿」や「防犯カメラのタイムスタンプ記録」 に相当する機能です。
    • 記録フォーマット:
      [YYYY-MM-DD HH:mm:ss] [操作元IP] [Action: 操作種別] [Target: 対象機器IP] 詳細メッセージ
    • 記録される主なアクション（Action種別）:
      • LOG_RETRIEVAL: 遠隔からの機器ログ取得（対象機器名、IP、実行コマンド、ステータス、終了コード、行数、サイズ、保存ファイル名、処理時間）
      • REMOTE_REBOOT: 遠隔からの機器再起動（対象機器名、IP、実行コマンド、終了コード、処理時間）
      • REMOTE_EXEC: 遠隔からのコマンド実行（対象機器名、IP、実行コマンド、終了コード、処理時間）
      • REMOTE_ERROR: リモート実行時の接続エラーや例外メッセージ
      • DEVICE_ADD, DEVICE_UPDATE, DEVICE_DELETE: 機器の追加・設定変更・削除
      • CONFIG_UPDATE: システム監視閾値や通知設定の変更
    • 画面上での確認手順（操作履歴モーダル）:
      1. ダッシュボード最上部のユーティリティバーにある 「🛡️ 操作履歴 (Audit Log)」 ボタンをクリックします。
      2. ポップアップ画面が開き、直近200件の操作ログが時系列で綺麗に一覧表示されます。
      3. 各行には「操作日時」「操作タグ（LOG_RETRIEVAL, REMOTE_REBOOT, REMOTE_EXEC など）」「対象機器」「実行コマンドや結果」が色分けされて表示されるため、誰がいつどんな操作を行ったかを直感的に点検・監査できます。
      4. 「閉じる」ボタンでいつでも通常の監視画面に戻れます。

11. 自動テストの実行手順（システムの品質保証・健康診断）

本システムには、ネットワーク監視やデータ記録、画面制御が常に正しく動作しているかを保証するための「自動テスト（総合健康診断）スイート」が標準装備されています。 システムのバージョンアップ後や運用前の定期点検として、誰でも簡単にワンクリックで全機能のテストを実行できます。

1. テストの実行方法

以下のいずれかの方法で簡単にテストを実行できます。

  • 方法A: ワンクリックで実行する（推奨・一番簡単）:
    • system\tests フォルダ内の Run-Tests.bat をダブルクリックします。登録している機器の設定を使わずに試すときは、開発者向けの Run-InCopy.ps1 を使うと、一時的なコピーの中だけでテストできます。
    • コマンドプロンプト画面が開き、全自動で全テストが順番に実行されます。
    • すべてのテストに合格すると [OK] すべての自動テストに正常合格しました。 と表示され、キーを押すと画面が安全に閉じます。
  • 方法B: PowerShell からコマンドで実行する:
    • PowerShell を開き、以下のコマンドを実行します：
      powershell.exe -ExecutionPolicy Bypass -File .\system\tests\Run-Tests.ps1
    • より詳細な実行結果（各テスト項目の合否）を画面で確認したい場合は、-VerboseOutput オプションを付けて実行できます：
      powershell.exe -ExecutionPolicy Bypass -File .\system\tests\Run-Tests.ps1 -VerboseOutput

3. テスト結果の見方と合格判定

テスト実行完了後、画面の最下部にサマリーが表示されます：

==========================================================
  Test Suite Summary (Pester 3.4.0)
==========================================================
  Total:   （テストの総数）
  Passed:  （合格した数）
  Failed:  0
==========================================================
[OK] すべての自動テストに正常合格しました。
  • Passed（合格数）: 正常にパスしたテスト項目の数です。
  • Failed（失敗数）: 0 であれば、自動テストの範囲では問題が見つからなかったことを示します。実機の OBR や SNMP 機器での動作は別途確認が必要です。

12. 専門用語のやさしい解説（初心者・運用者向け用語集）

現場の運用担当者や管理者が本システムをより直感的に理解できるよう、専門用語を日常生活のわかりやすい例えを交えて平易に解説します。

専門用語 日常生活に例えると 噛み砕いた解説
Runspace
(ランスペース)		 ひとつの会社の中で働く
「複数の専任作業員（個室）」		 パソコンの中で同時に複数の仕事をこなす仕組みです。「画面を表示する係」「0.1秒ごとにPingを飛ばす係」「SNMPでトラフィックを測る係」「レポートを書く係」など、独立した作業員（Runspace）が分担して同時に働くため、大量の通信を行っても画面が固まらず滑らかに動作します。
Pester
(ペスター)		 工場の出荷前チェックを行う
「厳格な自動検査官」		 Windows の PowerShell で作られたプログラムが仕様通りに正しく動いているかを、自動で一斉点検する仕組みです。人間が一つひとつボタンを押して確認しなくても、何十項目ものテストを数秒間で自動実行し、合格・不合格を判定してくれます。

(Jitter / 揺らぎ)		 電車の到着時刻の
「ばらつき（ダイヤの乱れ）」		 通信データの小包（パケット）が相手に届くまでの時間（Ping応答時間）の「ばらつき具合」を表す数値です（直近 30 回の遅延の差の平均で計算）。常に安定して届いていればジッターはほぼ「0」ですが、遅れたり早かったり乱れるとジッターが大きくなります。Web会議の音声途切れや監視カメラの映像カクつきの予兆を発見できます。
E2E
(End-to-End)		 車の製造ラインで完成車を

AST構文解析
(構文木チェック)		 本を出版する前の
「プロ校閲者による文法検査」		 プログラムを実行する前に、コードの文章構造（構文木）を細かく分解して、文法ミスやカッコの閉じ忘れ、不適切な書き方がないかをコンピューターが機械的にチェックする健康診断です。実行中の突然のエラーや誤作動を未然に防ぎます。
SNMP
(エス・エヌ・エム・ピー)		 機器が持っている
「健康診断用カルテの読み取り機」		 ルーターやスイッチなどのネットワーク機器から、現在の通信速度（トラフィック）やポートの状態などの内部情報を、機器に特別なソフトを入れずに直接聞き出す標準的な通信規格です。
パケット & ロス率
(Packet & Packet Loss)		 荷物を小分けにして送る「小包」と
「配達トラブル率」		 インターネット上ではデータは小さな塊（パケット）に分割されて送られます。回線の混雑やケーブル不良で相手に届かず消えてしまった小包の割合を「パケットロス率」と呼びます（0.0% が理想）。
ポート
(TCPポート)		 ひとつの建物（IP）の中にある
「たくさんの専用窓口（部屋番号）」		 1台のサーバーの中でも、「Webページを見せる窓口（80番/443番）」「メールを受け取る窓口（25番）」のように役割ごとに番号が分かれています。本システムでは、Pingだけでなく特定の窓口が開いているかを監視することも可能です。
SSH
(Secure Shell / セキュアシェル)		 強固な暗号化の鍵が付いた
「専用の安全な通信トンネル」		 離れた場所にあるLinuxサーバーやルーター、スイッチなどの機器と安全に通信し、遠隔操作を行うための世界標準規格です。やり取りされるデータやパスワードはすべて暗号化されるため、途中で盗聴されたり改ざんされたりする心配がありません。

(Windows Remote Management)		 社内Windows PCの裏口にある

「ログイン者専用の金庫」		 パスワードなどの秘密情報を保存する際、Windows OSがそのパソコンのログインユーザー専用の鍵を使って自動で暗号化する強固なセキュリティ技術です。設定ファイル（devices.json）を別のパソコンにコピーしても開くことができず、パスワード漏洩を防止します。

終了コード
(Exit Code / リターンコード)		 仕事が終わった作業員からの
「完了スタンプ（合否番号）」		 プログラムやコマンドが実行を終えたときに、正常に終わったかどうかを番号で知らせる仕組みです。一般的に「0」は「大成功・問題なし」を表し、1 以上の数字は「何らかのエラーや警告が発生した」ことを示します。
標準出力 / 標準エラー
(stdout / stderr)		 「普通のお返事の手紙（白）」と
「トラブル連絡の赤手紙」		 コマンドを実行した際に出てくるメッセージの通り道です。正常な計算結果や案内メッセージは「標準出力（stdout）」から、警告や失敗の原因メッセージは「標準エラー（stderr）」からそれぞれ返ってきます。
機器ログ
(Device Log / 機器カルテ)		 お医者さんが書く
「患者さんの健康カルテ・日記」		 ルーターやサーバーなどの機器自身が、「何時何分にどんな異常が起きたか」「どの通信回線が切れたか」を内部に書き溜めている公式の日記帳です。現地に行って画面を開かなくても、本システムから遠隔で安全に手元へ取り寄せることができます。
syslog / journalctl
(シスログ / ジャーナル)		 Linuxサーバーの
「時系列の日記帳・航海日誌」		 Linuxやネットワーク機器が動いている間に起きたすべての出来事（起動、ログイン、通信切断、プログラムのエラーなど）を秒単位で順番に書き記している標準的な記録台帳です。トラブルが起きた際、原因を突き止めるための最も重要な証拠になります。
イベントログ
(Windows Event Log)		 Windowsパソコンの
「システム活動記録簿」		 Windows OSが自動で記録している内部出来事の台帳です。「電源が落ちた」「ドライバーがクラッシュした」「ネットワークが切断された」などのシステム障害から、業務アプリのエラーまで詳細に記録されています。
ログローテーション
(Log Rotation)		 古い日記帳を箱にしまい
「新しいノートに取り替える作業」		 機器のログが際限なく増えてハードディスクをパンクさせないよう、一定の日数やファイルサイズごとに古いログを圧縮・退避し、常に最新の記録用のノートを用意する自動お掃除・世代管理の仕組みです。
パストラバーサル
(Path Traversal / 横断攻撃)		 立ち入り禁止の看板をすり抜けて
「裏口から侵入する不正な抜け道」		 ファイルをダウンロードする際に、../../ のようにファイルパスを遡る特殊な文字を悪用して、本来公開してはならない重要なシステムファイルや他人のデータを盗み見ようとするサイバー攻撃の手法です。本システムではこの抜け道を完全に遮断（ブロック）しています。
デーモン
(Daemon / 常駐プロセス)		 建物の裏で24時間休まず働く
「自動設備・見回りロボット（執事）」		 パソコンやサーバーの画面には直接現れず、バックグラウンド（裏側）で常に動き続けて決められた仕事（監視、ログ収集、通信の待ち受けなど）を休まずこなしてくれる常駐プログラムのことです。

13. よくある質問・トラブルシューティング

現象 原因と対処法
画面が開かない / 接続エラー バックグラウンドの PowerShell 画面が閉じられていないか確認してください。再度 Start-Monitor.bat を実行してください。
起動時の黒い画面（コマンドプロンプト / PowerShell）の文字化け防止について 本システムは、起動時に Start-Monitor.bat が文字コード（CP932 / UTF-8 BOM）の自動整合チェック（Ensure-Utf8Bom.ps1）と、日本語コンソールフォント（ＭＳ ゴシック）への自動切替保護を実行します。万が一、ファイルの編集後に文字化けが発生した場合は、再度 Start-Monitor.bat を実行することで文字コード（UTF-8 BOM）が自動修復されます。
Pingの応答があるのに、ステータスが「Warning」のまま戻らない / ロス率が100%になる（2026-10-28 修正済み） 旧バージョンでは、一度「Warning（黄色）」になると、それを「通信失敗」と数え間違える不具合がありました。そのため、応答があってもロス率が100%まで上がり、Warningのまま戻りませんでした。現在は「実際にPingの返事が返ってきたか」をもとにロス率・到達率・揺らぎ（ジッター）を計算するように修正しています。通信が安定すれば、自動で「Success（正常）」に戻ります。※修正前に記録された古いログ（CSV・報告書）の数値は、そのまま残ります。
画面上部に「サーバーとの接続が途切れています」と表示された バックグラウンドのサーバープロセスが一時的に高負荷になっているか、ネットワークが瞬断した可能性があります。本システムは自動復旧（Watchdog）を備えているため、通常は数秒〜十数秒待つと自動的に「サーバーとの再接続が完了しました」と表示されて復旧します。お急ぎの場合はバナー右側の「⚡ 今すぐ再接続」をクリックしてください。
Pingがすべてタイムアウト（赤）になる 対象機器側で Windows Defender ファイアウォール等の「ICMP Echo（Ping）の許可」が有効になっているか確認してください。
SNMPの情報（TX/RX）が取得できない 機器側のSNMPコミュニティ名（public等）または v3 認証情報が正しいか確認してください。
SNMP詳細情報が表示されない 取得できなかった場合は、SNMP詳細画面の「システム説明」欄に ⚠ から始まる原因 が表示されます。表示された内容に沿って、機器でSNMPが有効か、コミュニティ名／v3認証情報が一致しているか、UDP 161番ポートが遮断されていないかを確認してください。なお、2026-10-29 に「SNMPv3の機器でも常にv2cで問い合わせてしまう」不具合と、「Ping状態が正常のときしか問い合わせない」制限を修正しました（警告中の機器やPingを遮断している機器でもSNMP詳細を取得できます）。
超高速モード（0.1秒）で遅延グラフが時々消える / 縦軸が100msから変わらない（2026-10-29 修正済み） 旧バージョンではグラフの点が15個（0.1秒更新では1.5秒分）しかなく、「警告」中の値を空白として記録していたため、線がすぐ消えていました。また縦軸が最低100msに固定されていたため、数msの遅延は底に張り付いて見えにくくなっていました。現在は約30秒分を保持し、警告中も値を表示し、縦軸は遅延に合わせて自動調整されます。
超高速モード（0.1秒）で時々処理が止まる（2026-10-29 改善） 対象外機器（5秒間隔）の応答待ちで、応答しない機器1台につき最大0.05秒ずつ監視ループが止まっていた問題を修正しました。画面の更新も0.2秒ごとに抑えてサーバーの負担を減らしています。それでも重い場合は、①0.1秒監視の対象を本当に必要な機器に絞る、②0.1秒監視中は機器ログ取得・リモート操作・帯域計測など時間のかかる操作を控える、③使わない機器は監視を一時停止する、を試してください。
システム構成図で「リンク追加」「リンク削除」が有効かわからない ボタンを押してモードがONになると、リンク追加はオレンジ、リンク削除は赤で塗りつぶされて光り、ボタンの文字が「〜中（もう一度押すと終了）」に変わります。操作方法の案内も表示されます。もう一度ボタンを押すとOFFに戻ります。
無人運用モード（autoShutdownOnDisconnect: false）にしてもブラウザを閉じると監視が止まる（2026-10-30 修正） 起動処理の途中で設定が「標準（ブラウザを閉じたら終了）」に上書きされており、無人運用モードが働いていませんでした。修正後は、無人運用モードではブラウザを閉じても監視を続けます。「🛑 監視終了＆報告書」ボタンからは、どちらのモードでも終了できます。
ページを再読み込み（F5）したら監視が終了してしまった（2026-10-30 修正） 再読み込みのときも「ブラウザを閉じた」合図が送られるため、2秒以内に画面が戻らないと終了していました。待ち時間を10秒に延ばし、その間に画面が戻れば終了を取り消します。
Syslog が届かない Syslog / Trap 画面の上部の「受信状態」で、実際に受信しているポートを確認してください。514番が他のソフトに使われていると、自動的に 1514 番で受信します（機器側の送信先ポートを 1514 に合わせるか、514 番を使っているソフトを止めてください）。Syslog と SNMP Trap は、機器一覧に登録したアドレスから届いたものだけを表示します。「受信状態」に「未登録の機器から ○ 件を無視」と出ているときは、表示された送信元のアドレスを機器一覧に登録してください（機器によっては、管理用とは別のアドレスから送ることがあります）。
機器一覧の JSON インポートで既存の機器が消えた JSON インポートは「追加」ではなく、現在の機器一覧をファイルの内容にすべて置き換えます（2026-10-30 に確認メッセージをこの動作どおりに修正）。必要な機器を残したい場合は、先に「📤 JSON エクスポート」で現在の一覧を保存し、そのファイルに追記してからインポートしてください。なお、エクスポートファイル内の SNMPv3 パスワードは暗号化されており、エクスポートしたPC・Windowsユーザーでのみインポート後も使えます。
一括バックアップから復元しても機器一覧が戻らない（2026-10-30 修正） 以前のバージョンでは、一括バックアップ（設定＋機器）の書き出し形式に問題があり、復元しても「正常に復元しました」と表示されるだけで機器一覧が戻りませんでした。修正後は正しく戻ります。修正前に書き出したバックアップファイルも、そのまま復元に使えます。
起動時に「devices.json is broken」「RECOVERED」と表示された 機器一覧（devices.json）または設定（config.json）が壊れていて読めなかったため、system\backups の自動スナップショットのうち最も新しい読めるものから自動で復元しました。壊れたファイルは devices.json.broken_日時 として残してあります。復元内容が古い場合は、Web画面の「スナップショット復元」から別の時点を選んで戻してください。どのスナップショットも読めない場合は、機器一覧を空で上書きしないよう保存を止めた状態で起動します。
TCPポート監視にした機器が、ポートが開いていても常に「エラー / オフライン」になる（2026-10-30 修正） TCP接続を始める処理の書き方に誤りがあり、接続を試す前に必ず失敗していました。修正後は、ポートに接続できれば「正常」と表示されます。また、応答しない機器が他にあると TCP 監視の遅延が実際より大幅に長く（数百ms）表示され「高遅延」と誤判定されていた問題も、接続にかかった時間だけを測るように修正しました。
親機器のダウン中は通知が抑止されたのに、親の復旧時に子機器の「復旧」通知が大量に届いた（2026-10-30 修正） 復旧通知は、実際に障害通知を送った機器にだけ送るようにしました。親機器のダウンで障害通知を抑止した子機器からは、復旧通知も送られません。
SNMP Trap が届かない Syslog / Trap 画面の「受信状態」で受信ポートを確認してください（標準は UDP 162 番）。Windows の「SNMP Trap」サービスなどが使っていると 1162 番で受信し、その旨を黄色で表示します。その場合は該当サービスを止めるか、機器側の送信先ポートを 1162 に合わせてください。Windows ファイアウォールで UDP 162 番の受信を許可する必要がある場合もあります。受信できるのは v1 / v2c です。SNMPv3 の Trap は暗号化されていて読めないため、届いたことだけを表示します。
CSV で機器をまとめて登録・編集したい 「機器追加 / 管理」の「📤 CSV エクスポート」で Excel で開ける一覧を保存し、編集してから「📥 CSV インポート」で読み込みます。同じ IP の機器は更新、新しい IP は追加され、CSV にない機器は残ります（JSON インポートは全置き換えなので動作が異なります）。必須の列は「IPアドレス」だけで、ない列の項目は変わりません。パスワードは CSV に含まれません。ただしコミュニティ名（SNMP の合言葉）は含まれるので、ファイルの扱いにご注意ください。
SNMPv3 の設定方法 機器の登録・編集画面で SNMP バージョンを「SNMPv3」にすると入力欄が出ます。保存済みのパスフレーズは画面に表示されず、空欄のまま保存すれば今の値を使い続けます。認証方式を「なし」にすると消去されます。
機器までの通信経路を調べたい システム構成図で機器を右クリックして「🧭 経路トレース」を選びます。このPCからその機器までに通る機器を一覧で表示し、構成図に登録済みの機器は赤く光らせます。「応答なし」は、途中の機器が調査に応答しなかった区間です（通信できていないという意味ではありません）。調査には最大 30 秒ほどかかります。
PC 起動時に自動で監視を始めたい system\Service-Setup.bat を実行します。[2] は Windows にログオンしたとき、[3] は PC の起動時（ログオン前）に起動します。どちらも今のWindowsユーザーで動かすので、保存済みのパスワードを復号できます。[3] は登録時に Windows のパスワードを聞かれます。また、Google ドライブなどの同期ドライブはログオン前には使えないため、[3] を使う場合はプロジェクトを C ドライブなどへ移してください。以前 SYSTEM で登録したタスクは同じ名前で上書きされます。
起動時に「保存済みのパスワードを復号できません」と表示された パスワードは保存した Windows ユーザーでしか復号できません。保存したユーザーで起動し直してください。復号できない間もパスワードは消えません（暗号化された形のまま保持します）。別の PC へ移した場合は、パスワードを入力し直してください。
OBR の無線接続状況を見たい 「機器追加 / 管理」で OBR を編集し、「📶 OBR の無線接続状況を確認する」にチェックを入れて管理者パスワードを入力します。10秒ごとに確認し、ダッシュボードの機器カードとシステム構成図に、接続先の SSID・電波の強さ・通信速度を表示します（カードや機器にマウスを乗せると、チャンネルとアクセスポイントも見られます）。電波の強さは -67 dBm より弱いと黄色、-75 dBm より弱いと赤で表示します。未接続になると画面のアラートと音で知らせます（Webhook とメールは送りません）。パスワードは暗号化して保存しますが、OBR との通信自体は暗号化されない HTTP です。
OBR の無線状態の履歴を見たい ダッシュボードの機器カードで「📶」の無線の表示を押すと、今回の起動分の履歴が開きます。電波の強さと通信速度のグラフ（-67 / -75 dBm の目安線つき）と、切断・復旧・アクセスポイントの切り替えなどの出来事の一覧で、不調の原因を調べられます。長時間の記録は区間内の最小値に間引いて表示するので、短い電波の低下も隠れません。短い切断はグラフの途切れとして表示されます。記録は機器ごとに約 20MB までで、超えて古い記録が消えたときは画面に表示されます。自動では更新しないので、最新の状態は「更新」ボタンで読み直します。「確認できず」は OBR の管理画面に届かなかったという意味で、無線が切れたとは限りません。確認のたびに（10秒ごと）、Reports\起動日時のフォルダ\obr_wireless_IPアドレス.csv にも記録します。確認日時・状態・SSID・アクセスポイント・チャンネル・電波の強さ・通信速度が残るので、いつ切れたか、どのアクセスポイントに移ったか（ローミング）、電波がいつ弱くなったかを Excel で確認できます。10MB を超えると _1 付きのファイルに切り替わり、「ログ記録（CSV）」が OFF のときは記録しません。古いフォルダはログの保持日数に従って自動で削除されます。
OBR の表示が「🔒 ログイン失敗」「取得不可」になる 「ログイン失敗」はパスワードの誤りが主な原因です（機器側で拒否されないよう、5分おきに再確認します。パスワードを変更するとすぐ確認し直します）。「取得不可」は OBR の管理画面に接続できない状態です。IP アドレスと通信経路を確認してください。
機器ごとの監視ウィンドウ（Launcher.ps1）をまとめて閉じたい system フォルダの Stop-All.bat をダブルクリックします。各ウィンドウが結果を保存してから自動で閉じます。メインの監視画面には影響しません。
音声アラートが鳴らない ブラウザの自動再生ポリシーにより、画面の初回クリック操作後に音声が有効化されます。また、設定モーダルで「音声アラート」がONになっているか確認してください。
ディスク容量が心配 「ログ保守」機能で保持日数（例: 14日や30日）を設定すれば、古いログは自動的に削除されます。
自動テスト（Run-Tests.bat）でエラーが出た すでに監視サーバー（ポート8081等）が起動している場合は、一度画面から監視を終了させてから再度テストを実行してください。また、powershell.exe -ExecutionPolicy Bypass -File system\tests\Run-Tests.ps1 -VerboseOutput で詳細ログを確認できます。
リモート操作タブで「リモート管理が無効です」と表示される 対象機器の登録時に「リモート管理を有効にする」チェックが入っていません。画面左側の「デバイス管理」タブまたは機器カードから「編集」を開き、「🔧 リモート管理（再起動・コマンド実行）を有効にする」にチェックを入れて接続情報（プロトコルやユーザー名）を保存してください。
再起動やコマンド実行で「TIMEOUT（タイムアウト）」と表示された 対象機器への通信が届いていないか、相手機器側でSSH/WinRMサービスが起動していない、あるいはファイアウォールで通信ポート（SSHなら22番、WinRMなら5985番など）が遮断されている可能性があります。機器のIPアドレス、ポート番号、認証設定をご確認ください。なお、タイムアウトした処理は、そこから起動された子プロセスも含めて自動的に終了されるため、このPCに処理が残り続けることはありません。
機器ログ取得で「TIMEOUT（タイムアウト）」と表示された 対象機器への通信経路が遮断されているか、相手機器側でSSH/WinRMサービスが停止している、あるいはファイアウォールで通信ポート（SSH: 22番、WinRM: 5985番など）がブロックされている可能性があります。また、相手側で長いログを出力する際にキー入力待ち（ページャー）が発生している可能性もあります（本システムの標準プリセットを使用するか、コマンド末尾に --no-pager や行数制限を付けてお試しください）。
機器ログタブで「リモート管理が無効です (REMOTE_DISABLED)」と表示される 対象機器の登録時に「リモート管理を有効にする」チェックが入っていません。画面左側の「デバイス管理」タブまたは機器カードの「編集」から、「🔧 リモート管理（再起動・コマンド実行）を有効にする」にチェックを入れ、プロトコル（SSH/WinRM）や認証情報を入力して保存してください。
機器ログ取得で「認証失敗（Permission denied / ログオン失敗）」となる 登録されているユーザー名またはパスワードに誤りがあるか、そのユーザーに対象機器のログ閲覧権限（Linuxのroot/sudo権限やWindowsの管理者権限）が付与されていない可能性があります。機器の設定でユーザー名とパスワードを再入力して保存し直してください。
「出力サイズが1MBを超過したため画面表示を切り詰めました」と表示された ログのデータ量が非常に膨大なため、ブラウザ画面が固まるのを防ぐ安全機能（バッファ保護）が働いて画面上の表示を1MBで一時的に切り詰めています。サーバー側（Reports/device_logs/）には省略なしの全量ログファイルが完全な状態で丸ごと保存 されています。画面下の「📁 過去の取得ログ一覧」にある「📥 再ダウンロード」ボタンをクリックするか、直接ファイルを開くことで全量を確認できます。
過去に取得した機器ログはどこに保存され、どのようにバックアップすればよいか？ 取得された機器ログはすべて Reports/device_logs/ フォルダ配下に {IPアドレス}_{取得日時}.log という形式で恒久保存されます。このフォルダは定期的な過去ログ削除（パージ）の対象から除外されているため勝手に消えることはありません。バックアップしたい場合は、Reports/device_logs/ フォルダごと外付けドライブやファイルサーバーへ安全にコピーしてください。
保存したリモート接続パスワードの安全性は大丈夫か？ はい、安全です。Windows標準のDPAPI暗号化機能により、平文ではなく強固な暗号文字列（enc:...）として保存されます。第三者が設定ファイルをコピーしても解読できません。
間違えて再起動やコマンド実行ボタンを押してしまった 本システムでは必ず「二重確認ダイアログ」が表示されます。「キャンセル」ボタン、右上の「×」ボタン、または画面外をクリックして閉じることで、実際の処理は実行されずに安全にキャンセル（中断）されます。

14. エンタープライズ高信頼性・自動復旧機能・UI切断耐性

大規模・長期連続稼働（24時間365日）を支える信頼性向上機能です。

1. Watchdog による「ハングアップ・無応答」外形死活監視＆自己治癒

  • 概要: Start-Monitor.bat 起動時、内部で常駐する system/Watchdog.ps1 が 15秒間隔でサーバーの /api/health を外形監視します。
  • 死活＋健康状態の二重監視: プロセス自体の生存確認だけでなく、「内部のPing監視ループが正常にループし続けているか（スレッド停止・デッドロックが発生していないか）」を厳密に検査します。
  • 自動復旧（自己治癒）: 3回連続でタイムアウトまたは応答停止（503 Unhealthy）を検知した場合、ハングアッププロセスを自動強制終了し、3秒後に自動再起動します。短時間に5回連続クラッシュした場合はサーキットブレーカーが発動し安全停止します。（10分以上安定して動作すると、それまでのクラッシュ回数は0に戻ります）

2. 設定・機器構成の自動スナップショット＆ワンクリックロールバック

  • 概要: 機器の追加・編集・削除や、アラート閾値などの設定を変更した直前に、変更前の状態が system/backups/ へ最新20世代まで自動的に世代管理スナップショットとして退避されます。
  • ロールバック手順:
    1. 画面右上の 「⚙️ 設定」 を開きます。
    2. 「バックアップ・復元」 タブを開きます。
    3. 「🔄 自動スナップショット履歴＆ロールバック」 一覧から、戻したい日時のスナップショットの 「↺ この時点に戻す」 ボタンをクリックします。
    4. 確認ダイアログで「OK」を押すと、安全のため現在の状態も退避された上で、一瞬で以前の機器構成・設定に戻ります。

3. パケット損失率・ジッター異常による「回線品質劣化アラート」

  • 概要: 機器の完全停止（オフライン）だけでなく、Web会議の映像乱れや音声途切れ（VoIP品質悪化）、回線輻輳の前兆を検知する機能です。
  • 判定項目:
    • パケット損失率（%）: 直近30回のPing試行における損失割合（初期値: 5.0%）。
    • ジッター（ms）: パケット揺らぎの平均値（初期値: 20.0ms）。
  • 設定方法:
    • 設定モーダルの「監視・閾値」タブにある 「📶 回線品質劣化アラート」 で任意の閾値にチューニングできます。閾値を超過した機器は直ちに注意ステータス（Warning・黄色）へ遷移し、ダッシュボードおよび障害優先ソートで素早く把握できます。

4. 前提モジュール・システム診断チェックリスト（Web画面）

  • 概要: 監視動作に必要な PowerShell モジュールや計測ツールが正常に認識されているかを、ブラウザ上でチェックボックス形式で確認・自己診断できる機能です。
  • 確認・操作手順:
    1. 画面右上の 「⚙️ 設定」 を開きます。
    2. 「📋 前提モジュール診断」 タブを開きます。
    3. 各コンポーネントの状態が一目で確認できます：
      • [✔] SNMP 通信モジュール (PowerShell): インストール状況・バージョン・配置パス
      • [✔] Iperf3 帯域計測ツール (iperf3.exe): 利用可否
      • [✔] Pester 自動テストフレームワーク: インストール状況・バージョン
      • [✔] PowerShell 実行環境 & ポリシー: バージョン 5.1 適合性・ExecutionPolicy
    4. もし別の PC にコピーした直後などで SNMP モジュールが未検出の場合は、カード右側の 「⚡ 今すぐインストール」 ボタンをクリックするだけで、ブラウザからワンクリックで自動導入できます。

5. 🚨 IPアドレス競合（重複割り当て）自動検知と対処手順

  • 概要: 社内LANで誰かが既存機器と同じ固定IPアドレスを誤って設定した際、ARPテーブル（IPとMACアドレスの対応関係）の急変や不一致をバックグラウンドで自動監視し、即座に画面へ警告を発する機能です。
  • 画面の見方:
    • 競合が発生すると、ダッシュボード最上部に目立つ赤色グラデーションの 「🚨 IPアドレス競合を検知しました！」 バナーが表示されます。
    • バナーには「競合しているIPアドレス」「登録MACアドレス」「新しく応答してきたMACアドレス」が表示されます。
    • 該当機器のカードにも 「🚨 IP競合」 バッジが表示され、カード全体が赤くハイライトされます。
  • 対処手順:
    1. 警告バナーに表示された「検出MACアドレス」を確認します。
    2. スイッチのMACアドレステーブルや端末の物理アドレスと照合し、誤って同じIPを設定してしまった端末（持ち込みPCやプリンター等）を特定します。
    3. 誤設定された端末のIPアドレスを正しい値（またはDHCP自動取得）に変更します。
    4. 通信が正常に戻ると、システムが自動判定して数秒〜十数秒で警告バナーおよびカードのハイライトが自動消去されます。

6. 🛡️ フロントエンド切断検知＆シームレス再接続（UIレジリエンス）

  • 概要: 監視運用中にPCスリープや一時的なネットワーク瞬断が発生しても、監視画面が固まったり壊れたりせず、自動的に安全待機および復旧する高可用性UI機構です。
  • 特徴と動作:
    • 切断バナー表示: 3回連続で通信が遮断されると、最上部に #network-offline-banner が表示され、手動再接続ボタン（#btn-banner-reconnect）が提供されます。
    • シームレス自動復帰: サーバーが回復するとバナーが消滅し、✅ サーバーとの再接続が完了しました トーストが表示されて即座に監視を再開します。
    • 常時監視向け描画チューニング: トポロジー図の30 FPS間引き制御と Chart.js の .update('none') による高速描画により、長期間画面を開きっぱなしにしてもメモリリークや動作遅延が起きません。

7. ⏱️ 24時間365日 常時無人連続稼働モード（ブラウザ切断時自動停止の解除）

  • 概要: サーバールームや監視専用端末で、ブラウザ画面を閉じた状態でもバックグラウンドで休まず死活監視・ログ記録を続けさせるためのエンタープライズ連続運用機能です。
  • わかりやすい例え: 一般家庭のテレビで例えると「リモコンの電源連動機能（見ている人がいなくなったらテレビ本体の主電源も落とす）」に似ています。初期設定（autoShutdownOnDisconnect: true）では、画面からの定期的な合図（ハートビート）が途絶えると、PCの通信やCPU負荷を抑えるために監視サーバーも自動的に安全終了します。 無人運用モード（autoShutdownOnDisconnect: false）に設定すると、この連動が解除され、画面を閉じてもパソコンが起動している限り、バックグラウンドの監視スレッドが自律してPing監視とログ保存を休まず継続します。
  • 設定手順:
    • system/config.json 内の "autoShutdownOnDisconnect": false に設定して上書き保存します。
    • または、起動前に環境変数 NETWORK_MONITOR_AUTOSHUTDOWN=false を指定するか、Web画面の設定（/api/config）から切り替えることも可能です。
  • 耐障害性保証:
    • 監視ループは、監視対象のネットワーク切断やソケット例外（SocketException / TimeoutException）が発生しても、Runspace が落ちずに自律回復して監視ループ（LastPingLoopUtc）を進め続ける例外安全設計となっています。
